# 11.1 Public breach metadata (Have I Been Pwned)

`python -m cyber_risk_intelligence.breaches collect [--file breaches.json]`
`python -m cyber_risk_intelligence.breaches summary`
`python -m cyber_risk_intelligence.breaches access`  (what HIBP offers and what we can't see)

[Have I Been Pwned](https://haveibeenpwned.com/API/v3) (HIBP) publishes the metadata of every breach
it holds at `GET /api/v3/breaches`. It is free, needs no key, and is licensed CC BY 4.0, so we credit
Have I Been Pwned wherever the data is shown. The catalogue is about 1,050 breaches and about 1 MB.

## What HIBP lets us see

| capability | endpoint | access | used | what it means for us |
|---|---|---|---|---|
| breach catalogue | `/breaches` | public | yes | Metadata about breached sites: name, domain, dates, account count, data classes, flags. |
| one breach / latest breach | `/breach/{name}`, `/latestbreach` | public | no | Same data as the catalogue. |
| domain search | `/breachedDomain/{domain}` | paid key + verified domain | no | Needs proof that we control the domain (DNS record, email, file or meta tag). An unverified domain gets 403. We control none of the companies' domains, so **how many company addresses were breached is unknown, not zero**. |
| stealer logs by domain | `/stealerLogsByWebsiteDomain/...` | Pro key + verified domain | no | Infostealer exposure is unknown. |
| account / paste search | `/breachedAccount/{email}`, `/pasteAccount/{email}` | paid key | no | Searches individual people: out of scope (privacy). |

`HibpClient` only calls the public catalogue paths. Any other path, such as a domain, stealer-log,
account or paste search, raises `RestrictedEndpoint` before a request is sent, and no API key is
ever sent. These rows are written to `breach_source_access_notes` on each import.

## What a run does

* Downloads the catalogue, stores it whole as evidence, and inserts or updates one row per breach.
  The same catalogue again changes nothing (rows are `unchanged`).
* A breach with no `Name` is rejected into `ingestion_errors`. A bad date, domain or count is stored
  as unknown (NULL) with a warning, never guessed.
* A 429 rate limit (honouring `Retry-After`) or a server error is retried 3 times. If it still fails,
  nothing is imported and the stored catalogue stays as it was.

## Tables

| table / view | what it holds |
|---|---|
| `public_breach_metadata` | One row per breach, keyed by HIBP's stable `name`: `title`, `domain` (the breached site), `breach_date`, `added_at`, `modified_at`, `pwn_count`, `description` (HIBP's HTML), `data_classes`, the flags `is_verified`, `is_fabricated`, `is_sensitive`, `is_retired`, `is_spam_list`, `is_malware`, `is_stealer_log`, `is_subscription_free`, plus `disclosure_url`, `attribution`, `first_seen_run_id`, `last_seen_run_id` and `evidence_version_id`. |
| `breach_source_access_notes` | Per source and capability: `endpoint`, `access` (public / api_key / verified_domain), `used`, `returns`, `limitation`, `documentation_url`, `checked_at`. A check makes sure only public capabilities can be marked used. |
| `company_public_breaches` (view) | One row per company and breach when the breached domain equals (`same_domain`) or is a subdomain of (`subdomain`) one of the company's current domains. Adds `passwords_exposed` (if Passwords is among the data classes) and `in_latest_catalogue`. |

## Rules

* **Metadata, not credentials.** No email address, account, password or paste is collected or stored.
* **A link needs the domain.** A breach is linked to a company only through the company's own known
  domains. A breach named like a company but on another domain is listed in `summary` as *not linked*,
  until a source confirms the domain belongs to the company.
* **What a link means.** It means the company's own site or service was breached, so its customers' or
  users' records leaked. It says nothing about staff accounts that were exposed in other sites' breaches.
* **Missing stays missing.** A company with no linked breach may still have been breached (HIBP only
  holds breaches whose data surfaced). An unverified or fabricated breach keeps HIBP's flag and is shown.
* **History.** A changed breach updates its row and points to the new stored catalogue. The earlier
  values stay in the earlier catalogue. A breach HIBP removes keeps its row, and its `last_seen_run_id`
  shows the last import it was in.
