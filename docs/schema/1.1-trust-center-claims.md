# 1.1 Trust-center collection and security-control claims

Migration: `migrations/versions/0005_trust_center_claims.py`
Models: `src/cyber_risk_intelligence/models/controls.py`
Code: `src/cyber_risk_intelligence/collectors/trust_center/`

## Running it

1. Make a CSV of targets, with columns `company_key,url,page_type[,notes]`. See `docs/examples/trust_center_targets.example.csv`. Use only public pages.
2. Set a User-Agent that identifies you in `.env`, for example `COLLECTOR_USER_AGENT=cyber-risk-research/0.1 (contact: you@example.com)`.
3. Run:

```bash
python -m cyber_risk_intelligence.ingest run trust-center path/to/targets.csv
python -m cyber_risk_intelligence.quality
```

Running it again is safe. An unchanged page is recorded as `not_modified` and adds no claims.

## Tables

| Table | What a row means |
|---|---|
| `collection_targets` | A public page we collect for a company, with its page type (`trust_center`, `security`, `compliance`, `privacy`, `status`, `other`) and an `active` switch. |
| `page_fetches` | Every attempt to fetch a target: outcome, HTTP status, final URL, the stored page (evidence) and how many claims were found. |
| `security_control_claims` | A statement the company makes about its own controls: category, `affirmed` or `negated`, qualifier (for example `AES-256`, `TLS 1.2`, `SOC 2 Type II`), the exact sentence, its paragraph and heading, and the page's "last updated" date. Each claim points at the stored page it came from. |

## Fetch outcomes

| Outcome | Meaning |
|---|---|
| captured | page stored and claims extracted |
| not_modified | same content as an earlier capture; nothing new added |
| unavailable | 404, 5xx, network error or page over 5 MB |
| login_required | behind sign-in (401, or redirected to a login page) |
| blocked_by_robots | robots.txt disallows it, so it was not requested |
| rate_limited | the site answered 429; we stop calling that host for the rest of the run |
| not_html | a file type we don't read (images, old .doc/.xls/.ppt, other binaries), stored but not parsed |
| withheld | the page's visible text appeared to contain a credential, so it was not stored |

Many public pages embed browser keys (maps, search, analytics widgets) in their scripts and attributes. Those look like credentials, so when a captured page trips the secret check, the collector stores it **without** its scripts, styles, comments and any attribute value that looks like a key (`collectors/trust_center/scrub.py`), and says so in `page_fetches.message`. The visible text and `<meta>` tags are kept, so claims and dates are unaffected. A page only counts as withheld if its visible text still looks like it contains a credential. Pages that don't trip the check are stored byte-for-byte.

**An unreadable page tells us nothing about a company's controls.** It creates no claims, never removes earlier ones, and is never read as "control absent".

## Rules

* **Claims are claims.** `verification_status` is always `claimed`, enforced by a database check. Independent verification comes from other sources later.
* **Exact wording is kept.** Categories are normalized, but `claim_text` is the published sentence, with its paragraph and heading.
* **Negative statements are kept** as `negated` (for example "We do not support SSO on the Free plan").
* **History.** A changed page becomes a new evidence version with its own claims; older claims stay tied to the older capture.
* **Dates.** Publication time comes from page metadata and is stored on the evidence version. "Last updated" comes from metadata or page text and is stored on each claim as `page_updated_on`. If neither is given, both stay unknown.
* **Politeness.** The collector uses a declared User-Agent, follows robots.txt, waits 2 seconds between requests to the same host, and only fetches http(s).

## Limits (later issues)

* Pages built by JavaScript may yield few claims. Playwright rendering can be added behind the same `Fetcher` interface.
* PDFs (for example SOC 3 reports) are stored but not parsed.
* Extraction is keyword based. It finds candidate statements and does not judge them.


## PDFs

Security policies, SOC 3 reports and sustainability reports are often only published as PDFs. The collector reads them the same way as web pages (`collectors/trust_center/pdf.py`, using `pypdf`):

- The original PDF is stored byte-for-byte as evidence (`media_type = application/pdf`). PDFs up to 30 MB are fetched (web pages: 5 MB).
- Claims use the same matching as web pages. A claim's `section_heading` is the page it is on (`page 12`) and its `context_text` is the sentence with its neighbours, because PDFs don't have reliable paragraphs.
- `published_at` / `page_updated_on` come from the PDF's creation and modification dates, or a "Last updated" line.
- The secret check runs on the PDF's **text** (its raw bytes are compressed); a PDF whose text contains a credential is withheld.
- Scanned PDFs with no text layer are stored but yield no claims.


## Other document formats

`collectors/trust_center/documents.py` recognises a fetched file by its content (`%PDF-`, zip contents), its content type, or its file extension, and reads:

| format | typical use | `section_heading` of a claim |
|---|---|---|
| Web page (HTML) | trust centers, security pages | nearest heading |
| PDF | policies, SOC 3 reports, ESG reports | `page 4` |
| Word (.docx) | security whitepapers | nearest Word heading |
| PowerPoint (.pptx) | security overview decks | `slide 3` |
| Excel (.xlsx) | filled-in security questionnaires (CAIQ, SIG) | `<sheet name> row 12`; each row is read as `question \| answer` |
| Plain text (.txt), Markdown (.md) | security.txt, SECURITY.md | Markdown heading |
| JSON | bug-bounty platform policies | the JSON key path |

Office files are read with the standard library, with a 100 MB limit on their unpacked size. The secret check for every document format runs on its text. A broken file gives no claims and doesn't fail the run. Links inside text (`https://...`) no longer count as HTTPS/TLS claims.
