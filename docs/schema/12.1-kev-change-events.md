# 12.1 KEV change events

`python -m cyber_risk_intelligence.vulnerabilities kev collect`   (as in 5.1, now also records changes)
`python -m cyber_risk_intelligence.vulnerabilities kev changes [--days 30]`

Each KEV import is compared with what we already hold, and every difference becomes a row in
`kev_change_events`:

| change_type | when | what is kept |
|---|---|---|
| `added` | a CVE is in the new release that we didn't hold, or it came back after a removal | CVE, release, `date_added`, `required_action` |
| `updated` | CISA changed a listed field (vendor, product, name, description, date added, required action, due date, ransomware use, notes, CWEs) | `changed_fields`, `previous_values`, `new_values` |
| `removed` | the CVE was in the previous release we imported but not in the newest one | the last release it was in; the evidence is the newest catalog |

Every event points to its release (`release_id`), the stored catalog (`evidence_version_id`) and the
run (`ingestion_run_id`), plus `detected_at`. KEV entries carry no update time of their own, so the
release's `date_released` is when CISA published the change.

## Rules

* **An unchanged catalog adds no event**, and neither does a re-import of the same file. An older
  catalog imported after a newer one is ignored for changes.
* **Baseline.** The entries of the first catalog imported are `added` events with `baseline = true`
  (migration 0027 also marks the catalog already held as baseline), so alerts only fire on real changes.
* **No duplicates.** An update changes the one `kev_entries` row and adds one event. A removal is
  recorded once.
* `kev changes` lists non-baseline events and names any company whose latest exposure lookup lists the CVE.

## Running it regularly

CISA updates the catalog most weekdays. To build the change feed, run `kev collect` once a day. On the
Mac, a crontab line (`crontab -e`) that runs it at 7:00 is:

```
0 7 * * * cd ~/Documents/Codex/cyber-risk-intelligence && .venv/bin/python -m cyber_risk_intelligence.vulnerabilities kev collect >> data/kev-cron.log 2>&1
```
