# 2.1 Published backup frequencies

Migration: `migrations/versions/0011_backup_policy_claims.py`
Model: `src/cyber_risk_intelligence/models/backup.py`
Code: `src/cyber_risk_intelligence/backup/`

`backup_policy_claims` records what a company says on its own pages about how often it backs up,
what, how, and for how long. Every row is the company's own statement, so
`verification_status` is always `claimed`.

## Where rows come from

Rows are read from 1.1 `backup_and_recovery` claims (trust center, security pages, published
documents). The trust-center collector adds them as it collects; `backup derive` backfills them
from claims already stored. One sentence gives one row per schedule it states:
"daily full backups and incremental backups every 4 hours" gives two rows.

The 1.1 extractor now also picks up "back up" as a verb, snapshots and replication.

## What each row says

| column | meaning |
|---|---|
| `frequency_class` | `continuous`, `sub_hourly`, `hourly`, `sub_daily`, `daily`, `weekly`, `monthly`, `other`, or **NULL when the sentence gives no schedule** |
| `interval_minutes` | the interval when one is stated (daily = 1440, every 15 minutes = 15). Always NULL for `continuous` |
| `frequency_phrase` | the words the schedule was read from ("nightly", "every 4 hours") |
| `scope` | `own_practice`, `product_capability` ("you can schedule backups hourly"), or `customer_responsibility` ("customers are responsible for backing up") |
| `covered_system` | what is backed up, as the sentence names it ("customer data", "production databases") |
| `methods` | any of full, incremental, differential, snapshot, replication |
| `retention_days`, `rpo_minutes`, `rto_minutes` | when stated, with the phrase they came from |
| `quote`, `source_ref`, `evidence_version_id`, `claim_id` | the sentence, page URL, stored capture and 1.1 claim |
| `page_updated_on`, `observed_at` | the date the page states, and when we captured it |

## Rules

* **Daily and continuous stay apart.** Continuous replication has no interval; daily is 1440 minutes.
  Neither is turned into the other.
* **Not stated means unknown.** A sentence that mentions backups but gives no schedule is stored
  with `frequency_class` NULL. The `backup_frequency_not_stated` check (info) lists companies whose
  own backup statements never give a schedule.
* **A vendor's product text is not a customer's policy.** Product features and customer duties get
  their own `scope`, so they are not counted as the company's own practice, and nothing is copied to
  the vendor's customers.
* **Test and review schedules are not backup schedules.** "Our disaster recovery plan is tested
  annually" gives no row; "backed up nightly, restores tested quarterly" gives only `daily`.
* Negated statements keep `assertion = 'negated'` and are left out of the view.

## Running it

```bash
alembic upgrade head
python -m cyber_risk_intelligence.backup derive     # backfill from what 1.1 already collected; safe to repeat
python -m cyber_risk_intelligence.backup summary    # per company, scope and frequency
```

The `company_backup_frequencies` view gives one row per company, scope and frequency class with the
number of statements, the systems named, the shortest interval, retention range and best RPO/RTO.
