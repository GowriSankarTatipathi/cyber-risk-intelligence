# 1.3 Security certifications, attestations and authorizations

Migration: `migrations/versions/0007_security_assurances.py`
Model: `src/cyber_risk_intelligence/models/assurance.py`
Code: `src/cyber_risk_intelligence/assurance/`

A company saying it is ISO 27001 certified is a **claim**. It becomes **verified** only when an
independent register (IAF CertSearch, FedRAMP Marketplace, CSA STAR Registry ...) lists it. The
database enforces this: `verification_status = 'verified'` is allowed only on rows whose basis is
`issuer_directory`.

## Where rows come from

| basis | source | status |
|---|---|---|
| `company_claim` | an affirmed `compliance_certification` claim from 1.1 (trust center, security page) | claimed |
| `company_document` | a certificate or audit report the company publishes (PDF, Word ...), read for issuer, certificate number, dates and scope | claimed |
| `issuer_directory` | an entry copied from a public register, imported from CSV with its register URL | verified |

The trust-center collector (1.1) now adds the first two automatically. A page that only *mentions* a
standard ("we align with ISO 27001") is not treated as a certificate. A report gated behind an NDA
or "available upon request" is recorded with `report_availability = 'gated'`.

## Frameworks

| kind | frameworks |
|---|---|
| certification | ISO/IEC 27001, 27017, 27018, 27701, ISO 22301, ISO 9001, HITRUST, CSA STAR, TISAX, Cyber Essentials (+ Plus), CMMC |
| attestation | SOC 1, SOC 2 (with `report_type` Type I / Type II), SOC 3, PCI DSS, C5 |
| authorization | FedRAMP, StateRAMP, IRAP (`level` holds e.g. Moderate / High) |

GDPR, HIPAA, CCPA and NIST CSF are laws or frameworks without a certificate, so they stay as 1.1 claims only.

## Running it

```bash
alembic upgrade head
python -m cyber_risk_intelligence.assurance derive        # backfill from what 1.1 already collected; safe to repeat
python -m cyber_risk_intelligence.ingest run assurance-directory registers.csv   # optional: register entries
python -m cyber_risk_intelligence.assurance summary       # per company and framework
python -m cyber_risk_intelligence.quality
```

The register CSV format is in `docs/examples/assurance_registers.example.csv`. `record_url` must be an
https link on that register's own site (the allowed hosts are in `assurance/directory.py`), so a company
page can't be imported as verification. Copy entries from the registers' public search only; gated or
paid registers are not scraped.

## The summary view

`company_assurance_summary` has one row per company, framework and SOC report type:

| column | meaning |
|---|---|
| `status` | `verified` (an active, unexpired register entry), `verified_lapsed` (register entries exist but none is active and current), `claimed` (only the company's word) |
| `validity` | `current` / `expired` from the latest known `valid_until`; `unknown` when no date is known (unknown, not expired) |
| `public_report`, `gated_report` | whether a report is published or available only on request |
| `company_claims`, `company_documents`, `register_entries` | how many statements of each kind back it |

## Quality checks

| check | severity | finds |
|---|---|---|
| `assurance_verified_from_company_source` | error | a verified row whose evidence is the company's own website |
| `assurance_register_lapsed_but_claimed` | warning | the company still claims something its register entry shows withdrawn, suspended or expired |
| `assurance_claim_expired` | info | a claimed certification whose latest known date has passed |
