# 23.2 DMARC policy collection

Migration: `migrations/versions/0010_dmarc_policies.py`
Models: `src/cyber_risk_intelligence/models/email_security.py` (same tables as [23.1 SPF](23.1-spf-records.md))
Code: `src/cyber_risk_intelligence/email_security/dmarc.py`, `job.py` (`DmarcJob`)

DMARC tells receiving mail servers what to do with mail that fails SPF/DKIM alignment for a domain:
nothing (`p=none`, monitoring), send it to spam (`quarantine`) or refuse it (`reject`). It is a TXT
record at `_dmarc.<domain>`. We read it with ordinary DNS queries; no mail or report is sent and the
reporting addresses in the record are only recorded.

## Running it

```bash
alembic upgrade head
python -m cyber_risk_intelligence.email_security dmarc            # every known company domain
python -m cyber_risk_intelligence.email_security summary dmarc    # latest result again
```

## What is stored

Each lookup is a `dns_security_records` row (query name `_dmarc.<domain>`). Each observation is an
`email_security_observations` row with `control = 'dmarc'`:

| column | meaning |
|---|---|
| `status` | `present`, `missing`, `multiple`, `invalid` or `lookup_failed` (an NXDOMAIN for `_dmarc.<domain>` is `missing`) |
| `dmarc_policy`, `dmarc_subdomain_policy` | `none`, `quarantine` or `reject` (`sp` defaults to `p`) |
| `dmarc_pct` | share of failing mail the policy applies to (default 100) |
| `dkim_alignment`, `spf_alignment` | `strict` or `relaxed` |
| `aggregate_report_uris`, `failure_report_uris` | `rua` / `ruf` destinations as published |
| `tags` | every tag exactly as published |
| `defaults_used` | which of `sp`, `adkim`, `aspf`, `pct` were left out and took the RFC default, so "relaxed by default" and "relaxed as published" stay apart |
| `policy_source` | `domain`, or `organizational_domain` when a subdomain has no record and the parent's applies (`policy_dns_record_id` points at that lookup) |
| `problems` | what is wrong or weak. As receivers do, only a record without `v=DMARC1` first or without a usable `p` is `invalid` (a bad `p` with a valid `rua` is read as `p=none`); any other broken tag (bad value, malformed, repeated, unknown, a bad report address) is listed as "ignored by receivers" and its default applies. Also `pct` below 100 and no usable `rua` |

`latest_dmarc_observations` (view) has each company domain's most recent DMARC observation.

The organizational domain is approximated (last two labels, or three under `co.uk`-style
second-level names); it does not use the full public-suffix list.

## Quality checks

| check | severity | finds |
|---|---|---|
| `dmarc_lookup_failed` | warning | domains whose latest DMARC lookup failed (run again) |
| `company_domain_without_dmarc_lookup` | info | company domains never looked up, so their DMARC is unknown |
