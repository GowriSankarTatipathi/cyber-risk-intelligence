# 17.7 Evidence and historical storage

Migration: `migrations/versions/0002_evidence_storage.py`
Models: `src/cyber_risk_intelligence/models/evidence.py`
Code: `src/cyber_risk_intelligence/evidence/`

## Tables

| Table | What a row means |
|---|---|
| `sources` | Where we collect from (SEC EDGAR, GLEIF, a company site, an archive): type, access method, terms URL, licence, rate-limit note, and `is_permitted`. Collection from a source with `is_permitted = false` is refused. |
| `evidence_objects` | One distinct set of original bytes: SHA-256, size, media type, and its location in object storage (`minio` or `local`, bucket, key). Stored once, however many times it is captured. |
| `evidence_versions` | One capture of a URL: source, URL, title, HTTP status, and four separate times: `published_at`, `observed_at`, `archive_captured_at` (with `archive_url`) and `collected_at`, plus `last_seen_at`. |
| `evidence_links` | "This capture supports / contradicts / mentions that record", with an optional locator (field, XBRL tag, page). Exactly one target column is set. |

## How history works

* The same bytes from the same URL again: the version is reused and `last_seen_at` moves. Dates that were unknown are filled in if now known; known dates are never overwritten.
* Different bytes from the same URL: a new version. Old versions stay, so you can see what a page said on any collection date.
* The same bytes from two URLs: two versions, one object.

## Rules

* **Checksums.** Object keys are `sha256/<first 2 hex>/<sha256>`. `read_evidence` re-hashes the bytes and raises `ChecksumMismatch` if they changed.
* **Unknown stays unknown.** Every date except `collected_at` is nullable and is left NULL unless the source states it.
* **No secrets.** `record_evidence` scans content for private keys, cloud and GitHub tokens, JWTs, URLs with passwords and `password=` style assignments. Matching content is rejected before anything is written, and the error names only the kind of secret, never the value.
* **No orphans.** Links are real foreign keys (one nullable column per linkable table, `num_nonnulls(...) = 1`). Deleting a record deletes its links; a capture or source still in use cannot be deleted.
* **Conflicting evidence is kept.** Use `relation = 'contradicts'`.

## Usage

```python
from cyber_risk_intelligence.evidence import link_evidence, read_evidence, record_evidence, store_from_env

store = store_from_env()   # MinIO if MINIO_ENDPOINT is set, else ./evidence
v = record_evidence(session, store, source=sec, source_url=url, content=body,
                    media_type="text/html", published_at=filed_at)
link_evidence(session, v, legal_entity, locator="cover page")
original = read_evidence(session, store, v)
```

## Adding a linkable table

When a later issue adds a table that needs evidence, add a nullable `<singular>_id` foreign key to `evidence_links`, add it to `LINK_TARGETS`, and generate a migration (the check and unique constraints are rebuilt from `LINK_TARGETS`).
