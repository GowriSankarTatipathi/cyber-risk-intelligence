# 17.1 Company and legal-entity schema

Migration: `migrations/versions/0001_company_legal_entity_schema.py`
Models: `src/cyber_risk_intelligence/models/company.py`

## Tables

| Table | What a row means |
|---|---|
| `companies` | A research subject (a company group such as "Microsoft"). Everything we collect links back to one. |
| `legal_entities` | A registered legal person: an issuer or a subsidiary. May be unlinked (`company_id` NULL) until we know its group. |
| `entity_identifiers` | SEC CIK, LEI, ticker, OpenCorporates, EIN, DUNS. Each has an `issuer_scope` (e.g. `US-SEC`, `GLEIF`, `NASDAQ`) and a validity period. |
| `entity_relationships` | `child` *subsidiary_of / acquired_by / merged_into / successor_of / affiliate_of* `parent`, with dates and optional ownership %. |
| `company_aliases` | Legal, former, trade and brand names, abbreviations. |
| `domains` | One row per normalized hostname. |
| `company_domains` | Dated, sourced claim that a domain belongs to a company (role: primary website, trust center, IR, …). |
| `industry_classifications` | GICS, ICB, NAICS, SIC or a project group label. |
| `index_memberships` | "Company was in index X on date D", as observed. |

## Rules the database enforces

* **No duplicate identifiers.** The same `(scheme, issuer_scope, normalized_value)` cannot be active for two rows in overlapping periods (exclusion constraint over `daterange(valid_from, valid_to, '[)')`, needs the `btree_gist` extension). A ticker can move to a new entity after the old period ends. Unknown dates count as unbounded, so they conflict.
* **Identifier formats.** CIK is 10 digits, LEI is 20 characters (the ISO 7064 checksum is checked in Python by `normalize_lei`).
* **No orphans.** All links are foreign keys. A company that still has legal entities cannot be deleted.
* **Similar names are never merged.** `normalized_name` is indexed for search but not unique. "Apple Inc." and "Apple Hospitality REIT, Inc." are separate rows.
* **Time-bound relationships.** No overlapping periods for the same child, parent and type; an entity cannot be its own parent; `valid_to` is exclusive and must be after `valid_from`.
* **Provenance on every collected row**: `source_ref`, `verification_status` (`verified`, `observed`, `claimed`, `unverified`, `unknown`), `observed_at`, `collected_at`.
* **NULL means unknown, never absent.** Status columns default to `unknown`.

## Normalization (`cyber_risk_intelligence.normalize`)

* `normalize_cik("789019")` → `0000789019`
* `normalize_lei(...)` uppercases and verifies the check digits.
* `normalize_ticker`, `normalize_identifier(scheme, value)`
* `normalize_name("Nestlé S.A.")` → `nestle` (search only)
* `normalize_domain("https://www.Microsoft.com/x")` → `www.microsoft.com` (IDNA for non-ASCII)
