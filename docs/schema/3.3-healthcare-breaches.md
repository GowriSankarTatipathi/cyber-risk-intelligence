# 3.3 Healthcare breaches reported to HHS

`python -m cyber_risk_intelligence.incidents hhs collect [--list investigation|archive|both] [--file export.csv]`
`python -m cyber_risk_intelligence.incidents hhs summary`
`python -m cyber_risk_intelligence.incidents hhs candidates`  (find name candidates again and list them)
`python -m cyber_risk_intelligence.incidents hhs review ID --status confirmed|rejected --source URL [--note "..."]`

The [HHS OCR breach portal](https://ocrportal.hhs.gov/ocr/breach/) lists every breach of unsecured
protected health information that affected 500 or more people, as required by the HITECH Act. It is a US
government work (public domain). It has two lists: **under investigation** (reports from the last 24
months) and the **archive**. Together they hold about 8,100 reports from October 2009 onwards
(1.1 billion people affected in total, checked 2026-11-21).

## What a run does

* `HhsClient` opens the portal page and asks for the CSV export, the same way a browser's "Export as CSV"
  button does. The page is a JSF form, so this is a few form posts and needs no key. If the portal layout
  changes or the download fails after 3 attempts, nothing is imported for that list. You can then export
  the CSV from the portal by hand and import it with `--file` (with `--list` saying which list it is).
* Each CSV is stored whole as evidence. Each report becomes one row in `healthcare_breach_records`.
* After the import, `match_candidates` looks for our companies by name (see below), and the summary is printed.

## Identity of a report

HHS publishes no record id. A report is identified by the covered entity's normalized name, its state and
the submission date (`incident_key`). About 130 reports share all three with another report. These get
`same_day_seq` 1, 2, ... in list order and `ambiguous_identity = true`, so they are never merged into one.

A later download with a changed count, breach type, location, description, entity type, business-associate
flag or list (under investigation to archive) is a **new version of the same report, never a new incident**.
The row is updated, and the earlier values of the changed fields are appended to `revisions` together with
the stored CSV they came from. The same CSV again changes nothing.

## Rules

* **Submission date is not the breach date.** `submitted_on` is when the entity reported to HHS.
* **Missing stays missing.** A blank or non-numeric count is stored as unknown (NULL) with a warning, never 0.
  A report without an entity name or a valid MM/DD/YYYY date is rejected into `ingestion_errors`.
* **A name match is not the company.** Candidates are found by exact company name, legal-entity name or
  alias, or by a name that starts with ours ("Walmart Stores, Inc. Associates' Health and Welfare Plan").
  For a one-word company name, the next word must be corporate (Inc, Corporation, Stores, Health Plan,
  Benefits ...), so "Apple Valley Clinic" is not Apple. Every candidate stays `unverified` until someone
  records `confirmed` or `rejected` with a source URL (a press release, filing or news report). The
  database refuses a decision without a source.
* **Covered entity vs. business associate.** HHS lists the covered entity that reported. A breach at a
  vendor (business associate) may be listed under each affected health plan or provider instead.

## Tables

| table | what it holds |
|---|---|
| `healthcare_breach_records` | One row per HHS report: `incident_key`, `entity_name`, `normalized_name`, `state`, `entity_type`, `individuals_affected`, `submitted_on`, `breach_types`, `locations`, `business_associate_present`, `web_description`, `list_status` (under_investigation / archived), `same_day_seq`, `ambiguous_identity`, `revisions`, `first_seen_run_id`, `last_seen_run_id`, `evidence_version_id`. |
| `healthcare_breach_company_candidates` | Possible links from a report to a company: `match_basis` (exact_name / exact_alias / name_prefix), `matched_name`, `status` (unverified / confirmed / rejected), `review_source_url`, `review_note`, `reviewed_at`, `found_at`. |

First run in the cloud preview (2026-11-21): 693 under investigation and 7,400 archived reports. Name
candidates at 15 companies, for example Humana 22, Walmart 13, UnitedHealth Group 11, Iron Mountain 5,
CVS Health 3 and Cigna 3. None is confirmed yet.
