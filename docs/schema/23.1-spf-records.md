# 23.1 SPF record collection

Migration: `migrations/versions/0009_spf_records.py`
Models: `src/cyber_risk_intelligence/models/email_security.py`
Code: `src/cyber_risk_intelligence/email_security/` (SPF) and `src/cyber_risk_intelligence/domains/` (company domains)

SPF is a TXT record a domain publishes to list the servers allowed to send its email. We read it
with ordinary DNS queries through a recursive resolver, the same lookup any mail server makes.
Nothing is sent to the company and no email is sent.

## Running it

```bash
alembic upgrade head
# 1. Company domains (once, then whenever the list changes). A ready-made list for the 200
#    seed companies, from Wikidata's "official website", is in the project files.
python -m cyber_risk_intelligence.domains wikidata data/companies-200-seed.csv > data/company_domains.csv   # optional: rebuild it
python -m cyber_risk_intelligence.ingest run company-domains data/company_domains.csv
python -m cyber_risk_intelligence.ingest run company-domains data/company_domains_extra.csv   # mail/corporate domains from company pages
# 2. SPF for every known company domain
python -m cyber_risk_intelligence.email_security spf
python -m cyber_risk_intelligence.email_security summary
python -m cyber_risk_intelligence.quality
```

Set `DNS_RESOLVERS=1.1.1.1,8.8.8.8` in `.env` to use specific public resolvers; otherwise the
computer's own resolver is used. The resolver is recorded on every lookup. Running again is safe:
each run adds a new observation (so changes over time are kept), and an unchanged answer reuses
the stored copy.

## Tables

| Table | What a row means |
|---|---|
| `company_domains` (17.1) | A domain belongs to a company, with the page that says so (`source_ref`). Loaded by the `company-domains` job; `unverified`. |
| `dns_security_records` | One DNS query: name, type (`TXT`), resolver, time, outcome (`answered`, `no_records`, `nxdomain`, `lookup_failed`), the raw answer exactly as split into strings, TTL and the stored evidence. |
| `email_security_observations` | What that lookup shows for SPF: status, the record, its parsed mechanisms and modifiers, the `all` qualifier, terms that cost a DNS lookup, and problems found. `observed`, never `verified`. |
| `latest_spf_observations` (view) | Each company domain's most recent SPF observation. |

## SPF status

| status | meaning |
|---|---|
| present | exactly one SPF record that parses (problems may still be listed) |
| missing | the domain answered and publishes no SPF record |
| multiple | more than one SPF record; receivers treat this as an error |
| invalid | one SPF record that does not parse (unknown or malformed mechanism, bad IP) |
| no_domain | the name does not exist (NXDOMAIN) |
| lookup_failed | timeout, SERVFAIL, refused: **unknown**, never read as "no SPF" |

Problems flagged on a present record: more than 10 terms needing DNS lookups, `ptr`, `+all`,
terms after `all`, `redirect=` alongside `all`, records over 450 bytes. `include:` and `redirect=`
targets are recorded, not followed, so the lookup count covers this record only.

## Quality checks

| check | severity | finds |
|---|---|---|
| `spf_lookup_failed` | warning | domains whose latest SPF lookup failed (run again) |
| `company_domain_without_spf_lookup` | info | company domains never looked up, so their SPF is unknown |
