# 12.2 EPSS history

`python -m cyber_risk_intelligence.vulnerabilities epss collect [--date D]`   (today's file, as in 5.2, now logged)
`python -m cyber_risk_intelligence.vulnerabilities epss backfill --from 2026-10-01 [--to D] [--refetch]`
`python -m cyber_risk_intelligence.vulnerabilities epss trends [--days 30]`
`python -m cyber_risk_intelligence.vulnerabilities epss history --cve CVE-2021-40438`

FIRST publishes one EPSS file per day, and past days stay downloadable
(`epss_scores-YYYY-MM-DD.csv.gz`). Scores are kept per CVE and scoring day (`epss_scores`, unique on
`cve_id, score_date`), so history builds up as days are collected.

## What is new

* **`epss_collection_runs`** logs every attempt to collect a day: `imported` (with the stored file,
  model version, rows in the file and tracked rows stored), `not_published` (FIRST answered 404:
  that day is a **gap**) or `failed` (rate limit, server error, bad file; asked again next time).
  Migration 0028 adds the days already imported to the log.
* **Gaps stay gaps.** A day without an `imported` attempt has no scores. Another day's score is never
  copied into it, and `epss summary` / `backfill` list the gap days.
* **Idempotent.** Collecting a day again stores nothing new (the same file is the same evidence, and
  rows are `unchanged`). `backfill` skips days already imported unless `--refetch` is given.
* **Corrections kept.** If FIRST republishes a day with other numbers, the newer values are kept and the
  earlier ones are appended to `epss_scores.corrections` (epss, percentile, model, scored_at, evidence).
  They also remain in the earlier stored file.
* **Trends.** `epss trends` compares each own-IP CVE's first and last score in the window and lists the
  biggest rises, with KEV status and the companies whose IPs show the CVE.

## Notes

* Each stored day is about 3 MB of evidence. A 30-day backfill is about 90 MB.
* Run `epss collect` daily, for example next to the KEV crontab line in 12.1:
  `5 7 * * * cd ~/Documents/Codex/cyber-risk-intelligence && .venv/bin/python -m cyber_risk_intelligence.vulnerabilities epss collect >> data/epss-cron.log 2>&1`
* An EPSS score is about the CVE, never a company's chance of a loss.
