# 5.2 Exploit prediction scores (FIRST EPSS)

`python -m cyber_risk_intelligence.vulnerabilities epss collect`  (latest day)
`python -m cyber_risk_intelligence.vulnerabilities epss collect --date 2026-11-19`  (an earlier day)
`python -m cyber_risk_intelligence.vulnerabilities epss collect --file epss_scores-2026-11-20.csv.gz`
`python -m cyber_risk_intelligence.vulnerabilities epss summary`

[EPSS](https://www.first.org/epss/) (Exploit Prediction Scoring System, run by FIRST) publishes a free
CSV every day with two numbers for each published CVE:

* `epss`: the estimated probability (0 to 1) of exploitation activity against the CVE, anywhere,
  in the next 30 days;
* `percentile`: how that score ranks among all CVEs scored that day (0 to 1).

The first line of the file gives the model version and the scoring date
(`#model_version:v2026.06.15,score_date:2026-11-20T12:03:05Z`).

## What an import does

1. Downloads one day's file from `https://epss.empiricalsecurity.com/` (about 3 MB gzipped, about
   400,000 CVEs). A rate limit (429) or server error is retried 3 times; a day not published yet
   (404) is not. A failed download imports nothing.
2. Stores the whole file as evidence (17.7), so every CVE's score for that day can be read later.
3. Writes `epss_scores` rows only for the **tracked CVEs**: the CVEs Shodan inferred in the exposure
   lookups (10.3) and the CISA KEV entries (5.1). `--all` stores every CVE instead (slow; usually
   not needed because the file is kept).

A new day adds rows; an earlier day's scores are never overwritten. Importing the same file again
changes nothing.

## Tables

| table / view | what it holds |
|---|---|
| `epss_scores` | One row per (CVE, scoring date): `epss`, `percentile` (separate numbers, 0 to 1), `model_version`, `scored_at`, `evidence_version_id` (the stored day's file), `ingestion_run_id`. Unique on CVE + date. |
| `latest_epss_scores` (view) | Each CVE's most recent score. |

## Rules

* **Range.** A score or percentile that isn't a number between 0 and 1, or a malformed CVE id, is
  rejected into `ingestion_errors`; the database also refuses such values.
* **Missing is unknown.** A tracked CVE that isn't in the day's file has no row for that day; the
  summary counts these as unknown, never as a score of zero.
* **About the CVE, not the company.** EPSS estimates exploitation activity for a CVE across the
  internet. It is not a company's chance of being attacked or of a loss, and the summary says so.
  The summary lists CVEs Shodan inferred on companies' own IPs (unverified leads), KEV entries
  first, then by EPSS.
