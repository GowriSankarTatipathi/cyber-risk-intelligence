# 23.3 DKIM evidence

`python -m cyber_risk_intelligence.email_security dkim [--selectors published.csv]`

A DKIM key is published at `<selector>._domainkey.<domain>`, and the sender picks the selector.
Selectors can't be listed from DNS, and guessing names would be brute force, so only selectors known
from public evidence are asked:

1. **Providers named in the domain's own SPF record.** The SPF record is followed through its
   includes and redirects (at most 10 lookups, SPF's own limit). When it authorizes a provider that
   documents fixed selectors, those selectors are asked.

   | provider | SPF include | selectors |
   |---|---|---|
   | Microsoft 365 | `spf.protection.outlook.com` | `selector1`, `selector2` |
   | Google Workspace | `_spf.google.com` | `google` |
   | Mailchimp | `servers.mcsv.net` | `k2`, `k3` |
   | SendGrid | `sendgrid.net` | `s1`, `s2` |
   | Zendesk | `mail.zendesk.com` | `zendesk1`, `zendesk2` |

2. **Published selectors**, from a CSV `company_key,domain,selector,source_url` (for example a
   selector seen in the headers of an email the company published). A row without a `source_url`
   is ignored.

## `dkim_evidence`

One row per selector asked. The DNS answer itself is in `dns_security_records`, with its evidence.
Each row records how the selector is known: `selector_source`, `selector_evidence` (the SPF path,
e.g. `acme.com -> _spf.acme.com -> spf.protection.outlook.com`) and `selector_source_url` (the
provider's documentation or the published source).

| outcome | meaning |
|---|---|
| `key_found` | A DKIM key is published. `key_type` and `key_bits` are filled; RSA under 1024 bits is noted in `problem`. |
| `revoked` | A record with an empty `p=`: the key was withdrawn. |
| `invalid` | A record that isn't a usable key, or more than one DKIM record. |
| `not_found` | No DKIM key at this selector, including a domain whose wildcard TXT answers every name with something else (`problem` says so). This says **nothing** about other selectors. |
| `lookup_failed` | Timeout or server failure: unknown. |
| `no_known_selector` | One row for a domain with no selector known from public evidence: DKIM status unknown, never "no DKIM". |

`summary dkim` gives each domain one status: `key found`, `no known selector`, or
`unknown (no key at known selectors)`.
