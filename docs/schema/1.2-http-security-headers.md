# 1.2 Website security headers

`python -m cyber_risk_intelligence.http_security collect` checks each company's known website. It
asks the domain and, for a registered domain, its `www.` host. Each host gets two requests to the
home page, and only response headers are read:

* `https://<host>/`, following up to 5 redirects like a browser. The final answer's headers are graded.
* `http://<host>/`, to see whether plain HTTP sends the visitor on to HTTPS. Plain-HTTP hops are followed.

No other page, port or host is asked. The page body is not downloaded.

## Tables

| table / view | what it holds |
|---|---|
| `http_security_checks` | One row per host and run: `outcome` (`answered` / `request_failed`), final URL, redirect chain, `http_redirect` (`redirects_to_https`, `no_redirect`, `redirects_elsewhere`, `request_failed`), `assessment_version`, and the evidence of the kept headers. |
| `http_security_observations` | For an answered check, one row per header: raw value(s) (one per line when sent more than once), `value_count`, `result`, `note`. |
| `latest_http_security_checks` | The newest check of each host. |

A failed request (timeout, refused, TLS error, redirect loop) has no header rows. A site we couldn't
reach is never counted as missing headers.

## Grading (`cri-headers-1`)

Simplified from the MDN HTTP Observatory's guidance. Every check stores its `assessment_version`, so
results can be reproduced from the stored headers.

| header | pass | weak | invalid |
|---|---|---|---|
| Strict-Transport-Security | `max-age` ≥ 180 days | shorter, or `max-age=0` | no valid `max-age` |
| Content-Security-Policy | a script policy without the gaps listed under weak | scripts allow `'unsafe-inline'` (without nonce/hash), `'unsafe-eval'` or any host; or no script/default policy | empty |
| X-Frame-Options | `DENY` / `SAMEORIGIN`, or CSP `frame-ancestors` | | anything else (`ALLOW-FROM` is ignored by browsers) |
| X-Content-Type-Options | `nosniff` | | anything else |
| Referrer-Policy | `no-referrer`, `same-origin`, `strict-origin`, `strict-origin-when-cross-origin` | `unsafe-url`, `no-referrer-when-downgrade`, `origin`, `origin-when-cross-origin` | nothing recognised |

* `missing` means the site answered and didn't send the header.
* A header sent twice with different values is `invalid`, except CSP: several CSP headers all
  apply, so one strong policy is enough.
* `Permissions-Policy`, `Cross-Origin-Opener-Policy` and `Content-Security-Policy-Report-Only` are
  kept as `info`.

The evidence keeps only these headers plus the URLs and redirects. Cookies and dates are left out,
so nothing secret is stored and an unchanged answer reuses the stored copy.
